# 만원 실험실

## 단타 돌파와 실시간 피드백 · v1.3

**실제 주문 기능이 없는 모의 실험입니다. 단타·점수 보정의 수익 개선 효과는 검증되지 않았습니다.** 최신 웹 버전의 신규 방문자는 단타 모드로 준비하며, 기존 장부는 원래 모드와 기록을 유지합니다. 기존 사용자는 `실행할 모드 → 단타 돌파 → 전략 적용 → 모의매매 시작/재개`로 바꿀 수 있습니다. 모의 보유분이 있을 때는 먼저 정리해야 합니다. 변경해도 원금·24시간 종료 시각·손실 한도·거래 횟수·실현손익이 초기화되지 않습니다.

| 규칙 | 추세 관찰 | 단타 돌파 |
| --- | --- | --- |
| 진입 | MA5/MA20와 5분 상승률 | 5분 고점 돌파 + 거래량 증가 |
| 최대 보유 | 30분 | 5분 |
| 재진입 대기 | 10분 | 1분 |
| 하루 신규 진입 상한 | 5회 | 30회 |
| 비용 반영 손절 / 익절 | −1% / +1.8% | −0.6% / +1.2% |
| 추적 청산 | 없음 | 순수익 +0.6% 도달 후 고점에서 0.3%p 하락 |

단타는 연속 마감 1분봉 16개를 요구합니다. 종가가 직전 5개 봉의 최고가보다 0.01% 이상 높고, 거래량은 직전 10개 봉 평균의 1.3배 이상, 최근 3분 상승률은 0.15~2.5%, 최근 1분 상승률은 0.05% 이상, 마지막 봉 종가는 전체 가격 범위의 상단 35% 안, MA3 > MA10일 때 후보가 됩니다. 미완성 봉·거래 없는 분을 임의로 채워 판단하지 않습니다. 신호 유효기간은 해당 봉 시작 후 125초입니다.

단타의 모의 진입에는 호가 간격 0.12% 이하, 호가 잔량으로 계산한 예상 왕복 비용 0.35% 이하를 추가로 요구합니다. 매수 예상 체결가가 신호 종가보다 0.4% 넘게 올랐거나 최우선 매수호가가 돌파 기준선 아래이면 보류합니다. 매수뿐 아니라 매도 잔량도 확인합니다. 비용·잔량 검사를 통과하지 못한 후보 대신 다음 후보를 검사합니다.

웹 단타 후보는 기존 투자유의·주의 및 최소 거래대금 필터를 통과한 거래대금 상위 60개 안에서 고릅니다. 먼저 거래대금 상위 6개를 포함하고, 나머지 6개는 로그 거래대금 45%와 당일 고저 변동폭 55%의 합산 점수로 고릅니다. 변동폭 기여는 15%에서 상한을 두며 후보 목록은 5분마다 재선정합니다. 이 점수는 기대 수익률이 아닙니다. 시세·분봉 수신 후 매초 진입과 청산을 평가합니다. 로컬 서버 버전은 기존 4개 종목과 약 10초 조회 간격을 유지합니다.

### 실시간 피드백

- 완료된 **단타 모의 매도**의 비용 반영 수익률만 반영합니다. 미청산 평가이익·실거래 수동 입력·추세 모드 성적은 표본에 섞지 않습니다.
- 종목별 최근 최대 8회 결과 중 3회부터 평균 수익률에 따라 진입 후보 점수를 0.65~1.15배로 보정합니다. 한 번의 수익률 기여는 ±3%로 제한합니다. 가격 조건·손절·최대 투입금을 자동 완화하지 않습니다.
- 같은 종목에서 2회 연속 손실이면 그 종목을 마지막 손실 후 20분간 신규 진입에서 제외합니다. 전체 단타에서 3회 연속 손실이면 마지막 손실 후 15분간 신규 진입을 보류합니다. 기존 보유분 청산은 계속 평가합니다.
- 이는 정해진 범위의 성과 피드백이며 AI 모델 재훈련이나 수익 보장 기능이 아닙니다. 표본이 작거나 시장 상황이 바뀌면 보정이 오히려 불리할 수 있습니다. 장부를 바탕으로 새로 계산하므로 새로고침 후에도 반영됩니다.

`전략별 실현 성적`에는 청산 횟수·승률·평균 순손익·누적 수수료를 표시합니다. 각 모드의 실행 시점이 다르므로 동일 기간 비교나 백테스트 결과가 아닙니다. CSV에 전략과 체결 사유도 포함합니다. 이전 버전의 전략 표시 없는 모의 기록은 추세 모드로 집계합니다.

## GitHub Pages 웹 버전

GitHub Pages의 정적 사이트로 실행할 수 있습니다. `docs/`만 게시 대상이며 별도 서버·계정 비밀키·유료 API가 필요하지 않습니다. 웹 주소에는 언제든 접속할 수 있지만 **모의매매는 페이지가 열려 있는 동안만 실행됩니다.** 탭 종료·PC 절전·모바일 백그라운드에서 감시가 멈출 수 있습니다. 24시간 서버 운영을 뜻하지 않습니다.

웹 버전의 추세 모드는 업비트 원화 종목 전체를 조회해 투자유의·주의 표시가 없고 24시간 거래대금이 10억 원 이상인 종목 중 거래대금 상위 12개를 정밀 관찰합니다. 단타 모드는 위의 거래대금·변동폭 순위를 사용합니다. 전체 목록과 선정·제외 사유를 검색할 수 있습니다. 목록과 거래대금 순위는 5분마다 갱신하며, 전체 목록의 가격은 조회 시점 기준입니다. 보유 종목이 순위 밖으로 나가도 청산 시세 감시는 유지합니다. 현재 원화 마켓에서 제외된 종목의 보유 기록은 보존하며 없는 시세로 체결을 만들지 않습니다.

선정한 종목은 공개 WebSocket으로 현재가·호가·1분봉을 받습니다. REST로 과거 45개 캔들을 순서대로 준비하고 약 5분마다 보완하며, 최신 분봉은 WebSocket으로 유지합니다. 브라우저 Origin 요청 제한을 고려해 REST·연결·구독 변경 사이에 최소 12초를 둡니다. 처음 12종목 준비에 약 3분이 걸립니다. 캔들 공백은 임의로 채우지 않으며 마감된 25개 연속 1분봉만 사용합니다. 연결 복구 후 캔들을 다시 확인할 때까지 신규 신호를 보류합니다. 목록·거래대금 갱신 실패 또는 10분 이상 오래된 후보 정보로는 신규 진입하지 않습니다.

관찰 범위 확장은 수익률 개선이 검증됐다는 뜻이 아닙니다. 동시 보유 1종목, 원금 1만~10만 원, 투입·손절·손실 중단 규칙은 같습니다. 자동 모의매매만 제공하며 실제 돈을 벌거나 실제 주문을 전송하지 않습니다.

기록은 방문자의 브라우저 저장소에만 보관합니다. GitHub 또는 다른 방문자에게 전송되지 않습니다. 다른 기기와 동기화되지 않으며 브라우저 데이터를 삭제하면 기록도 없어집니다. CSV로 기록을 내보낼 수 있습니다. 한 브라우저의 여러 탭에서 동시에 모의매매가 실행되지 않도록 잠금을 사용합니다. 재접속 시 신규 진입은 일시정지됩니다.

로컬 서버 버전과 웹 버전의 장부는 독립적입니다. 기존 로컬 기록이 공개 사이트로 자동 업로드되지 않습니다. 실제 주문·계정 연결 기능은 없습니다.

게시 파일 갱신:

```powershell
node scripts/build-pages.mjs
node --test
```

GitHub 저장소의 **Settings → Pages → Deploy from a branch → codex/github-pages /docs**로 게시합니다. `docs/`는 생성된 정적 파일만 포함합니다. `data/`, 비밀키, `.env`, 로그는 Git에 포함하지 않습니다.

아래 내용은 기존 로컬 서버 버전의 실행 안내입니다.

업비트 공개 시세를 이용하는 **1만~10만 원 자동 모의매매 실험**과 **사용자가 직접 입력하는 실거래 장부**입니다. 실제 주문 전송, 계정 연결, 자금 이체 기능은 없습니다. API 키를 입력할 필요가 없습니다.

## 실행

Node.js 22 이상이 필요합니다. 추가 패키지 설치는 없습니다.

Windows에서는 `start.cmd`를 더블클릭하세요. 로컬 서버를 숨김 창으로 실행하고 브라우저를 엽니다. 이미 실행 중이면 기존 서버를 사용합니다.

터미널에서 실행하는 방법:

```powershell
cd "coin-lab"
node server.mjs
```

주소: http://127.0.0.1:8787

터미널에서 실행한 서버는 Ctrl+C로 종료합니다. `start.cmd`로 실행한 서버는 `stop.cmd`로 종료할 수 있습니다. PID와 전체 스크립트 경로가 일치하는 해당 Node 프로세스만 종료합니다.

## 사용 순서

1. 실험 원금을 10,000~100,000원 범위에서 1,000원 단위로 정하고 **원금 설정 적용**을 누릅니다. 기본값은 10,000원입니다. 두 장부는 각각 독립적인 같은 원금을 기준으로 하며 합산 자산이 아닙니다.
2. **자동 모의매매**에서 시작을 누르면 그 시점부터 24시간 동안 공개 시세로 규칙을 평가합니다. 실거래 금액은 사용되지 않습니다. 신호가 없으면 거래하지 않습니다.
3. **실거래 기록**은 업비트에서 직접 실행한 실제 거래의 체결가·수량·수수료를 시간순으로 입력하는 장부입니다. 주문을 보내는 버튼이 아닙니다. 앱이 표시한 예상 체결가를 실제 체결가로 입력하지 마세요.
4. 손익과 CSV를 확인합니다. 잘못 입력했다면 마지막 입력을 취소하고 다시 입력할 수 있습니다. 취소 이력은 보관됩니다.

실험 시작 또는 체결 입력 후에는 원금 변경을 막습니다. 데이터 초기화 버튼이 없으므로 결과를 지우고 수익처럼 다시 표시하지 않습니다. 실거래 장부의 입력 취소는 실제 거래소 주문에 영향을 주지 않습니다. 부분 체결은 주문액 5,000원 미만일 수도 있으므로 수동 장부에는 이를 허용합니다. 부분 체결별 ID는 서로 달라야 합니다.

## 모의 전략 v1.0

수익성이 검증되지 않은 고정된 추세 규칙이며 AI로 시장을 예측하지 않습니다. LLM API를 호출하지 않아 모델 사용료는 없습니다. 인터넷·전기·실제 거래 수수료 등은 별도입니다.

- 로컬 서버 버전은 BTC, ETH, XRP, SOL의 업비트 KRW 마켓을 관찰합니다. GitHub Pages 웹 버전의 전체 원화 마켓 선별 방식은 위 설명을 참고하세요.
- 25개 연속 마감 1분봉이 있어야 신호를 계산합니다. 현재 진행 중인 캔들은 제외합니다.
- 5봉 평균이 20봉 평균보다 0.03% 이상 높고, 최근 5분 상승률이 0.08~0.8%이며, 호가 간격이 0.15% 이하이면 진입 후보입니다.
- 후보 중 평균 격차와 상승률 합계가 가장 큰 한 종목만 보유합니다. 초기 원금의 최대 90%를 수수료 포함 투입합니다. 예: 1만 원 → 최대 9,000원, 10만 원 → 최대 90,000원.
- 청산 비용을 반영한 포지션 수익률 −1% 손절 / +1.8% 익절, 추세 이탈 또는 보유 30분 경과 시 모의 매도합니다.
- 매도 후 10분 대기, 같은 캔들에 재진입하지 않으며 KST 날짜별 신규 진입 최대 5회입니다.
- 원금 대비 손실 5% 또는 시작 후 24시간 경과 시 실험을 잠그고 보유분 정리를 시도합니다. 가격 급변, 최소 주문액 미달, 데이터 지연으로 손실은 이 수치를 초과할 수 있습니다.
- 일시정지는 신규 진입만 중단합니다. 기존 모의 보유분의 매도 조건은 계속 감시합니다. 보유분까지 즉시 정리하려면 **모의 보유분 전량 정리**를 사용합니다.

## 비용과 데이터 정확도

- 업비트 공개 REST GET으로 현재가·호가를 약 10초 간격으로 조회하고, 1분봉은 약 60초 간격으로 갱신합니다. 장애 때 조회 간격을 늘립니다.
- PC 시계의 작은 오차는 공개 API의 HTTP Date 헤더로 보정합니다. 시스템 시각을 변경하지 않으며 차이가 5분을 넘으면 시세 처리를 보류합니다.
- 호가 잔량을 순서대로 소진해 체결가를 계산합니다. 편도 거래금액의 0.05% 수수료와 편도 0.05% 추가 슬리피지를 가정합니다. API 스냅샷 사이의 변동·지연·매매 순서·체결 실패를 완전히 재현하지 못합니다.
- 실제 계정의 수수료 정책은 계정 화면에서 확인해야 합니다. 모의 수수료는 시뮬레이션 가정입니다.
- 평가액은 현금 + 보유분 예상 매도대금 − 예상 매도수수료입니다. 실현손익은 평균 매입원가(매수 수수료 포함)를 배분해 매도 시 계산합니다. 세금·입출금 비용은 계산하지 않습니다.
- 보유분 시세가 없으면 평가액을 `—`로 표시합니다. 오래된 시세가 남아 있으면 이전 시세임을 표시합니다. 모의 체결은 30초 이상 지연된 호가로 실행하지 않습니다.
- 실거래 장부의 현금과 실현손익은 **사용자 입력 기준**입니다. 거래소와 대조되지 않았으며 앱 밖의 입출금이나 기록하지 않은 거래를 감지하지 못합니다. 현물 매수·매도만 지원합니다.
- 차트는 실제 관찰 시점만 저장하며 과거 거래를 만들어 넣지 않습니다. 서버 중단 구간은 선을 끊어 표시합니다. 화면은 최근 100개 체결을 표시하고 CSV에는 전체 체결이 포함됩니다.

## 실행 지속과 보관

브라우저를 닫아도 Node 서버가 켜져 있으면 계속 실행됩니다. PC 절전, 종료, 네트워크 중단 때 거래 감시가 멈춥니다. 서버 재시작 시 신규 진입은 일시정지되며, 시세가 복구되면 기존 모의 보유분의 매도 조건을 감시합니다. 중단 구간의 거래를 소급 생성하지 않습니다. 24시간 실험 기간에는 중단된 시간도 포함됩니다.

장부·체결·관측·로그는 `data/experiment.json`에 저장합니다. 임시 파일에 쓰고 동기화한 다음 교체하며, 저장 오류가 나면 신규 진입을 중단합니다. 손상된 저장 파일을 자동으로 빈 장부로 덮어쓰지 않습니다. 자동 시작이나 Windows 예약 작업은 등록하지 않습니다.

서버는 `127.0.0.1`에만 바인딩합니다. Host 및 Origin 확인과 세션 토큰으로 다른 사이트의 변경 요청을 막습니다. 외부 요청은 `api.upbit.com`의 공개 시세 GET 경로로 제한했습니다. 주문·출금 엔드포인트와 계정 비밀키 코드가 없습니다.

## 검증

```powershell
node --test
```

계산·비용·부분 매도·지연 시세·캔들 시점·예산별 한도·손실 중단·최소 주문액을 단위 테스트합니다. HTTP 통합 테스트는 별도 임시 폴더에만 테스트 장부를 만들고, 원금 범위·중복 체결·원금 고정·CSV·재시작 복원·입력 취소·교차 출처 차단을 확인합니다. 실제 장부나 계정을 사용하지 않습니다.

`PORT`로 포트, `LAB_DATA_DIR`로 별도 저장 경로를 지정할 수 있습니다. 테스트와 실제 실험은 서로 다른 저장 폴더를 사용해야 합니다.
